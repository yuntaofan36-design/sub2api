# 企业管理

企业功能仅在标准运行模式且开放用户面板时启用。新增 `enterprise_admin`（企业负责人），角色仍存放在 `users.role`，不继承平台管理员或团队管理员的全部权限。

| 角色 | 入口 | 范围 |
| --- | --- | --- |
| `admin` | `/admin/enterprises`、`/admin/teams` | 企业开通、负责人任免、已有团队关联和所有资源授权 |
| `enterprise_admin` | `/my-enterprise` | 所属企业内团队设置、创建团队管理员、提拔本团队成员或撤销管理员、团队级统计和管理记录 |
| `team_admin` | `/my-team` | 所属团队成员、邀请、Key、资源发放和团队用量 |
| `user` | `/my-team` | 本人的团队 Key、用量、获配记录和退出 |

企业负责人使用蓝色标识，团队管理员继续使用橙色。负责人保留个人中心和个人资源使用能力。平台团队表格增加企业信息和筛选，已有独立团队保持原有行为。

## 使用流程

1. 平台从有效且未加入团队的普通账号中选择首位负责人，创建企业。之后可任命多名负责人。一个负责人只关联一个企业，不得兼任团队成员。
2. 企业负责人登录后默认进入仪表盘的「企业」视图，可切换「个人」，通过「我的企业」进入管理。创建团队时必须同时填写全新团队管理员的邮箱、用户名和初始密码，账号与团队在同一事务中创建。余额为零，不发注册奖励或默认订阅；已有邮箱（含受保护别名）不能接管。
3. 新团队没有分组授权、余额或订阅配额，由平台在团队管理中授权。负责人只能修改团队名称和状态，不能修改资源授权。
4. 后续可创建更多新管理员，或从目标团队的有效普通成员中提拔管理员。撤销管理员后保留普通成员关系；已被平台停用的管理员账号也可撤销身份，停用状态保持不变。已有外部账号由平台引入，不开放企业级全局用户搜索、管理员邀请或跨团队调任。
5. 平台可以把独立团队关联到企业。负责人随即获得该团队的历史团队级汇总和管理记录；不允许再次转移或移除归属。

正常企业和正常团队分别必须保留至少一名有效负责人、团队管理员。事务锁和延迟数据库约束共同保护并发任免，也覆盖原用户管理的角色修改、停用和删除入口。任免提交后失效相关缓存，登录资料重新读取当前角色、企业或团队状态；页面在刷新、切换及现有用户资料自动刷新时更新权限。

## 停用与隐私

平台停用企业后，网关实时拒绝新的团队调用，企业负责人及团队管理员禁止管理写入。历史查询保留，平台可以恢复企业、维护负责人和资源。企业状态独立于各团队状态：恢复企业不会启用原先单独停用的团队。已获准执行的请求仍完成并保留提交时的团队归属；个人 Key、余额及已发订阅继续遵循原规则。

企业负责人默认只能查看团队级请求数、Token、用户计费金额、可分配余额、剩余订阅份数、授权分组以及团队管理员摘要。组织汇总包含成员在队期间的个人 Key 与团队 Key 用量；平台按企业启用 `allow_member_usage_view` 后，额外开放成员姓名、邮箱、关系状态和聚合用量。不返回个人财务、完整 Key、逐条请求、提示词或平台上游成本，也不能调用团队日常管理接口。使用显式角色及归属校验，不扩张 `IsAdmin` 或 `can_manage`。

企业及团队治理成功记录保存操作者、目标、变更前后信息；失败及敏感操作沿用原审计记录，密码字段脱敏。企业管理记录仅合并企业自身事件与团队设置、管理员任免、平台拨款和订阅授权事件，不包含成员个人资源发放明细。

## 接口

新增接口只接受登录 JWT；平台全局管理 API Key 不能作为企业或团队管理员身份。敏感写入复用现有 step-up 验证。

| 接口 | 用途 |
| --- | --- |
| `GET/POST /api/v1/admin/enterprises` | 平台企业列表、企业和首位负责人创建 |
| `GET/PUT /api/v1/admin/enterprises/:enterpriseID` | 详情、名称、状态及成员用量查看开关设置 |
| `GET /api/v1/admin/enterprises/leader-candidates` | 搜索有效且无团队的普通用户 |
| `PUT /api/v1/admin/enterprises/:enterpriseID/leaders/:userID` | `promote: true/false` 任免负责人 |
| `PUT /api/v1/admin/enterprises/:enterpriseID/teams/:teamID` | 关联独立团队 |
| `GET /api/v1/admin/enterprises/:enterpriseID/{teams,administrators,stats,events}` | 平台按企业查询 |
| `GET /api/v1/enterprise/current` | 从当前用户关系确定企业 |
| `GET /api/v1/enterprise/{teams,administrators,stats,events}` | 当前企业团队、管理员、统计和记录 |
| `POST /api/v1/enterprise/teams` | `name`、`status`、`administrator: {email,username,password}` 创建团队和首位管理员 |
| `GET/PATCH /api/v1/enterprise/teams/:teamID` | 团队详情；仅编辑名称、状态 |
| `GET /api/v1/enterprise/teams/:teamID/administrator-candidates` | 目标团队有效普通成员及管理员候选 |
| `POST /api/v1/enterprise/teams/:teamID/administrators` | 创建全新管理员账号 |
| `PUT /api/v1/enterprise/teams/:teamID/administrators/:userID` | 任命或撤销当前团队管理员 |

列表支持 `page`、`page_size`，每页最多 200 条。统计支持 `team_id`、`from`、`to`，默认最近 30 天，日期格式为 RFC3339，左闭右开。企业管理记录支持 `team_id`。平台团队列表支持 `enterprise_id`，`0` 为全部、`-1` 为独立团队。负责人接口不接受客户端企业归属作为授权依据。

## 数据与启动

新增 `242_enterprises.sql`，不修改已应用的团队迁移：新建企业、负责人关联、企业操作记录，并给团队增加可空 `enterprise_id`。旧团队和历史数据不自动归属企业。没有企业删除、多企业负责人、跨企业转移或企业共享钱包。

本地更新后重新启动后端，会自动执行增量迁移；刷新前端即可使用新入口。无需重新安装前端依赖。

## 组织仪表盘

`/dashboard` 对企业负责人、团队管理员默认展示组织统计，`?scope=personal` 展示原个人仪表盘。普通用户和平台管理员的原仪表盘保持不变。

- `GET /api/v1/enterprise/dashboard`：企业汇总、趋势、请求模型分布、前十二个团队排行和当前能力。允许 `team_id` 筛选本企业团队。
- `GET /api/v1/teams/current/dashboard`：当前团队管理员的团队汇总及成员排行。团队归属由登录用户确定。
- 在以上接口后追加 `/members` 获取分页成员汇总，追加 `/members/:userID` 获取成员汇总详情；企业成员详情必须指定 `team_id`。普通用户无整体统计权限。
- 日期使用 `start_date`、`end_date`（YYYY-MM-DD，含结束日期），`timezone` 使用 IANA 时区，默认 UTC；默认最近七个自然日。支持 `granularity=day|hour`，每日最多一年、每小时最多 31 天。成员分页默认 20 条，最多 100 条。
- 企业成员查询每次读取当前企业开关，默认关闭。开关仅由平台设置，修改记录进入企业操作日志；关闭不影响团队级汇总。成员统计以团队和用户组合归并历次成员关系。
- 用量时间轴按入账时间，归属按请求提交时间。可分配余额、剩余订阅份数、当前成员数量不受用量日期范围影响；资源发放额与消费额分开展示。

迁移 `243_organization_dashboards.sql` 新增企业开关、`request_submitted_at` 和独立的 `organization_team_id` / `organization_membership_id`。原 `team_id` / `team_membership_id` 继续表示团队 Key 归属。旧个人记录按入账时间匹配历史成员区间，找不到关系时不归属组织；旧长请求跨离队时点可能存在偏差。新请求携带准入时间，批量图片任务保存提交时间、视频结算复用创建时快照，迁移 `244_organization_admission_snapshot.sql` 将准入时读取的成员关系随同步、流式、WebSocket 每轮、异步图片/视频和 Live 会话一并传递；入账不使用结算时的当前团队。没有快照的历史任务才按提交时间匹配历史关系。团队 Key 始终保留其不可变归属。

仪表盘改造在隔离数据库和服务中完成以下实际操作验收：

- 企业、团队及普通用户登录；组织／个人切换；平台仪表盘兼容；团队筛选、成员分页与汇总详情；桌面及手机布局。
- 企业成员开关关闭、开启及再次关闭，关闭后成员接口返回 403、页面清除成员数据；跨企业和跨团队访问被拒绝，成员响应不包含财务、Key 或请求明细。
- 同步与流式调用经过本地模拟上游、真实扣费和入库；混合 Key 的企业、团队、模型汇总金额一致，加入前的个人用量不纳入组织。
- 请求开始后离队再完成，归属仍保留原成员关系；离队后的新个人请求不归属团队；重新加入后使用新关系，成员汇总合并历次在队记录，旧团队 Key 仍被拒绝。
- 企业停用后组织仪表盘保持只读，团队 Key 拒绝新请求，个人 Key 仍可调用；撤销团队管理员后旧身份接口返回 403，页面清除组织内容并回到个人视图。
- 小时粒度、时区、非法日期和越权筛选；批量图片任务归属字段入库及既有读取接口兼容，包括提交时无团队的任务。
