# 团队管理

团队功能用于标准运行模式且开放用户面板的部署。角色统一为 `admin`、`enterprise_admin`、`team_admin`、`user`；团队归属存放在独立成员关系中，不再存一份团队角色。

## 使用入口

- 平台管理员：`/admin/teams`，创建团队、指定已有普通用户为管理员、任免管理员、授权分组、拨付或撤回未发余额、授权订阅份数。
- 我的团队：`/my-team`，团队管理员与普通成员共用一个入口。有效团队管理员登录后默认进入团队概览，页面展示成员、邀请、团队 Key、资源发放、用量和流水管理；普通成员仅能查看本人的团队 Key、用量及获配记录，并可退出团队。管理员仍可复制自己的团队 Key，需要先由平台或所属企业负责人撤销管理身份才能退出。
- 原团队管理地址 `/team` 自动跳转到 `/my-team`。页面按最新用户角色和后端返回的团队管理权限显示内容，团队、所属企业或成员暂停后收起管理操作。
- 邀请链接：`/team-invite?token=…`，已有用户登录后确认接受。仅受邀邮箱对应的普通用户可接受，七天有效、一次使用、可撤销。

平台团队列表直接展示各团队管理员的姓名、邮箱及停用状态，团队管理员使用橙色标识。每行的「编辑」管理团队设置，「查看」进入团队详情，「更多」提供管理员任免、余额拨付/撤回和订阅授权；这些操作在列表弹窗内完成，保存后刷新当前列表。

启动新版后端时会自动运行增量迁移 `241_teams.sql`。本地前后端分别运行时，重新启动后端并刷新前端即可。平台可先在原用户管理页创建普通用户，再在团队管理页任命；原用户管理页不能直接授予或撤销 `team_admin`。

## 资产与权限

团队余额是可分配额度。发放时同一事务扣减团队余额、增加成员个人余额并写入流水。个人充值不会增加团队额度，也不会提高团队 Key 限额；已发余额离队后保留，团队发放不触发个人充值返佣。

订阅授权保存分组、每份天数和总份数。每次发放消费一份，复用原有开通或续期逻辑；已发订阅不会因离队被撤销，离队或到期不返还份数。新的授权规格使用新记录。

团队 Key 固定绑定团队、成员关系和用户。团队授权分组与成员本身的分组使用资格必须同时满足。管理员只能在创建时获得完整 Key；管理列表脱敏，之后仅持有者能通过本人入口读取。原个人 Key 修改、删除及重置入口拒绝修改团队 Key。

团队 Key 的请求明细和导出仅统计团队 Key。团队管理员仪表盘及管理概览另行汇总成员在队期间的个人 Key 与团队 Key 用量，只提供聚合请求数、Token 和用户计费金额，不开放个人 Key 请求明细、上游成本、提示词或私人充值订单。「我的团队」按角色展示数据：普通成员仅能查看本人的数据，有效团队管理员可查看团队范围的数据。完整 Key 始终仅允许本人读取。

暂停团队或成员立即阻止新的团队调用，个人调用仍按原规则处理。离队永久停用旧成员关系的团队 Key；再次加入会生成新成员关系，旧 Key 不会恢复。用量和批量图片任务保留原团队、原成员关系。

## 接口与实现

所有新增接口使用登录 JWT。团队接口不接受平台全局管理 API Key。

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/admin/teams` | 分页列出团队，包含当前管理员摘要 `administrators`（已退出或已删除账号不返回） |
| `POST /api/v1/admin/teams`、`PUT /api/v1/admin/teams/:id` | 创建团队、更新名称/状态/授权分组 |
| `PUT /api/v1/admin/teams/:id/administrators/:userID` | `promote: true/false` 任免管理员 |
| `POST /api/v1/admin/teams/:id/funding` | 正数拨付、负数撤回未分配余额 |
| `POST /api/v1/admin/teams/:id/grants` | 授权固定天数、固定份数的订阅 |
| `GET /api/v1/teams/current`、`GET /api/v1/teams/:id` | 当前归属与概览 |
| `/api/v1/teams/:id/members`、`/invitations` | 成员创建、状态调整、邀请创建与撤销 |
| `POST /api/v1/teams/invitations/accept`、`POST /api/v1/teams/:id/leave` | 本人加入、退出 |
| `/api/v1/teams/:id/keys`、`/keys/:keyID`、`/keys/:keyID/secret` | 团队 Key 管理与本人读取 |
| `POST /api/v1/teams/:id/allocations` | 发放余额或一份订阅 |
| `GET /api/v1/teams/:id/grants`、`/ledger`、`/usage`、`/usage/export` | 订阅配额、流水、用量和 CSV |

列表支持 `page`、`page_size`（每页最多 200 条）；用量支持 `member_id`、`key_id`、`model`、`from`、`to`，日期为 RFC3339，区间左闭右开，默认最近 30 天。CSV 最多导出 10,000 条，超过时需缩小时间范围。`mine=true` 可进一步限定本人数据，不会扩大任何权限。

拨付、订阅授权和资源发放要求 `operation_id`（8–100 字符，前端使用 UUID）。同一团队、同一标识和同一请求重试返回原结果；标识对应不同请求返回 409。金额使用字符串，最多八位小数。余额发放示例：

```json
{
  "kind": "balance",
  "member_id": 123,
  "amount": "10.00000000",
  "operation_id": "a-unique-request-id"
}
```

实现位于 `backend/internal/team`，通过 Ent 事务复用原用户创建和订阅服务。数据库部分唯一索引限制一个用户只有一条未退出关系；延迟约束检查团队管理员归属、平台管理员不得加入团队、正常团队至少保留一名有效管理员。团队变更使用事务锁，与原用户角色/状态变更协调；资源更新有余额、份数下限和幂等唯一约束。

网关对团队 Key 每次重新读取策略，并检查当前企业、团队、成员、用户、分组及订阅资格；权限读取失败时拒绝请求。提交后失效相关 Key、余额及订阅缓存。个人 Key 沿用原鉴权和计费路径。

Key 归属由数据库禁止更改。用量与批量图片任务插入时通过触发器从不可变 Key 归属写入快照，因此退出后完成的请求仍归属原团队。原 Key 归属列不推断旧数据；新增组织统计列的历史回填和提交时间规则见企业管理文档。团队流水记录操作者、目标及变更前后信息；失败操作及敏感读取沿用原管理面审计。

## 本次验证

未编写测试用例。后端编译、前端类型检查、修改文件 ESLint 检查及 Vite 构建通过。构建仍有现有的分包大小和 Browserslist 提示。

在独立 PostgreSQL 数据库、独立 Redis 和临时服务端口中进行了实际页面和 API 操作：创建团队、任免管理员、创建和邀请成员、幂等及并发余额发放、订阅开通和续期、Key 创建和额度调整、跨团队拒绝、个人接口绕过拒绝、暂停/恢复、离队/重新加入、历史归属、个人用量隔离及 CSV 导出。个人兑换充值增加个人余额，团队额度保持不变。简单模式和仅后台模式均拒绝新增团队接口。

页面验证包含平台拨款、团队创建成员、发放余额以及成员只读入口；390px 与 1440px 宽度下均无页面横向溢出。

模型调用使用本地模拟 OpenAI 上游，经过实际网关鉴权、计费和用量落库，验证了团队统计与个人余额扣费。已转发的请求在成员离队后仍能完成，并保留原成员关系归属。未使用真实付费模型上游或外部支付渠道；真实图片批处理和第三方登录回调未进行端到端验证。

企业负责人的能力、企业停用行为及接口见 [企业管理](ENTERPRISES.md)。
